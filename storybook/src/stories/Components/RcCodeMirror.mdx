# RcCodeMirror

A code editor built on CodeMirror 6 for YAML and JSON documents. Bind the document with `v-model`. Language, keymap, theme, variant, read-only, line numbers, fold gutter and line wrapping can all change after mount.

The default `rancher` theme uses the Rancher light or dark palette from the surrounding `theme-light` or `theme-dark` class. Use `theme="none"` to inherit surrounding styles instead.

## Keymaps

Set `keymap="emacs"` for Emacs movement, undo, kill/yank, and multi-key commands. Browser shortcuts still take priority when the browser reserves them; for example, Chrome intercepts Ctrl-N and Ctrl-W before the editor receives those keys.

CodeMirror renders only the lines in view, so the browser's own find cannot reach the rest of a long document. In the editor variant, Ctrl-F (Cmd-F on macOS) opens CodeMirror's search panel instead; with Emacs outside macOS, Ctrl-S opens it, since Ctrl-F moves forward a character. Enter and Shift-Enter, F3 and Shift-F3, or Mod-G and Shift-Mod-G move between matches, and Escape closes the panel. Vim searches with `/`. The input variant leaves Ctrl-F to the browser. The panel's labels can be translated through `EditorState.phrases`.

Set `keymap-indicator` to show a button in the top-right corner while the Vim or Emacs keymap is active, so users know why keys behave differently. Selecting it hides it until the editor is remounted and moves focus into the editor. It is never shown for the default keymap or the input variant.

## Accessibility

CodeMirror renders its own textbox, so ARIA attributes such as `aria-label`, `aria-labelledby` and `aria-describedby` are forwarded to it rather than the component's root element. Every instance needs an accessible name from one of them. A `<label for>` does not work, because the textbox is not a form control; give the label an `id` and reference it with `aria-labelledby`, as the input example below does.

In the editor variant, with the default keymap and in Vim Insert mode, Tab fills from the cursor to the next indent stop using the document's indent unit (two spaces by default), or indents the selected lines. Shift-Tab unindents. With Emacs, Tab reindents the line and Shift-Tab unindents. In Vim Normal mode, Tab moves forward in the jump list and Shift-Tab does nothing. A hint appears while the editor is focused: press Escape then Tab (or Escape then Shift-Tab) to leave, as described in [CodeMirror's Tab guidance](https://codemirror.net/examples/tab/). This works with every keymap. In the input variant and in a read-only editor, Tab and Shift-Tab move focus normally and the hint is not shown.

Escape pressed in the editor stays in the editor: it does not propagate to the page, so it will not close a surrounding modal while leaving Vim's Insert mode, for example.

Folds can be toggled from the keyboard with every keymap:

| Action | Windows / Linux | macOS |
| --- | --- | --- |
| Fold the line at the cursor | Ctrl-Shift-[ | Cmd-Alt-[ |
| Unfold the line at the cursor | Ctrl-Shift-] | Cmd-Alt-] |
| Fold everything | Ctrl-Alt-[ | Ctrl-Alt-[ |
| Unfold everything | Ctrl-Alt-] | Ctrl-Alt-] |

## Input

The `input` variant is a multi-line form input rather than a code editor. It has no gutters, uses the body font and is styled like the other form inputs. Line breaks are marked with ↵ so values that contain them are distinguishable.

With the `rancher` theme, syntax colors and the caret match the editor palette while the input keeps its form background, border, spacing and selection.

## Custom folding

`foldOptions.strategy` picks how fold ranges are found: `language` (the default) uses the language's syntax tree, `indent` folds by indentation and `bracket` folds matching brackets.

The package also exports fold services for the `extensions` prop and imperative helpers to call from the `ready` event:

- `foldByLineMatch(pattern)` and `foldMatchingLines(view, pattern)` for lines matching a regular expression
- `foldByYamlPath(path)` and `foldYamlPath(view, path)` for a dot-notation YAML path such as `metadata.labels`
- `commentFoldService` and `foldAllComments(view)` for nested comment blocks

This story folds `spec` and `metadata.labels` on load. Changing its fold strategy in Controls remounts the editor so the new strategy takes effect.

## Linting

Pass a `@codemirror/lint` source as `linter` to check the document. It returns the problems as diagnostics, which are underlined in the text with their message on hover. In the editor variant a gutter between the line numbers and the fold gutter also marks the lines with problems; the input variant has no gutters, so it only underlines them. The source runs shortly after the document stops changing, and the prop can change after mount.

## Translations

Pass CodeMirror translations through the `extensions` prop. The host application can use its own i18n system to supply the translated strings:

```ts
import { EditorState } from '@codemirror/state';

const extensions = [EditorState.phrases.of({
  'Fold line': t('codeMirror.foldLine'),
  'Unfold line': t('codeMirror.unfoldLine'),
  'Press Escape, then Tab to leave the editor': t('codeMirror.escapeText'),
  // `$` is replaced with the translated keymap name
  'Key mapping: $': t('codeMirror.keymap.indicatorToolip', { name: '$' }),
  'Hide key mapping: $': t('codeMirror.keymap.hideIndicator', { name: '$' }),
  'Vim': t('prefs.keymap.vim'),
  'Emacs': t('prefs.keymap.emacs')
})];
```

`<RcCodeMirror :extensions="extensions" />` uses these phrases for the fold controls, the escape hint and the keymap indicator's tooltip and label. The `extensions` prop is read on mount, so remount the editor when changing its locale.
